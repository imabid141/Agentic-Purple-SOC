# 🧠 Phase 2 Deep-Dive: The Intelligence Bridge

**Turning Static Telemetry into Agentic Reasoning**

## 1. Objective
The goal of Phase 2 was to engineer a custom "middleware" that connects the **Wazuh Indexer** (Data Storage) to **Llama 3.2** (Local Inference). This allows the SOC to move from simple alerting to automated threat triage.

---

## 2. Technical Architecture
To maintain a 100% private, air-gapped security environment, I developed a Python-based Intelligence Bridge that operates entirely on local hardware.



### Key Components:
* **Data Source:** Wazuh Indexer (OpenSearch-based REST API).
* **Inference Engine:** Ollama running Llama 3.2 (3B Parameters).
* **Integration Logic:** Custom Python scripts utilizing `requests` for telemetry extraction and the `ollama` library for local LLM orchestration.

---

## 3. Engineering Challenges & Solutions

### A. The Authentication Barrier (401 Unauthorized)
**Problem:** The initial connection to the Indexer API was rejected. This was a critical learning moment regarding Dockerized security—the Indexer and Dashboard, while related, maintain separate internal credential databases.\
**Solution:** Conducted low-level `curl` probes against the REST API to identify the correct internal administrative credentials, eventually securing the handshake using verified environment variables.

### B. Contextual Prompt Engineering
**Problem:** Raw logs are "noisy" and difficult for standard LLMs to interpret without context.\
**Solution:** Developed a **Cyber Analyst Persona**. By wrapping the raw log in a structured system prompt, I forced the AI to focus on specific security KPIs: Summary, Threat Level, and Response Actions.
